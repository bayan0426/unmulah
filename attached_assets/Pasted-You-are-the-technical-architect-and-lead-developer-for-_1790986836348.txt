========================
PROJECT VISION
========================

UNMULAH is a Sign-first intelligent Islamic accessibility platform designed primarily for Deaf people and sign-language users.

The initial focus is Quran learning and memorization review.

The long-term vision is broader:
Quran learning → trusted Islamic knowledge → introduction to Islam → new Muslim learning journey → other Islamic educational experiences.

However, the hackathon MVP must stay focused and realistic.

========================
CORE PROBLEM
========================

Many Quran recitation-assessment tools are voice-first.

A hearing user can recite into a microphone and receive automated feedback.

A Deaf/sign-language user does not have an equivalent integrated experience for:

Learn → Hide → Recite visually → See what AI understood → Detect errors → Correct → Track progress.

UNMULAH aims to fill this interaction gap.

========================
MVP CORE FLOW
========================

The MVP should initially work end-to-end with one Surah only:

Surah Al-Ikhlas.

After the complete flow works, other short Surahs may be added.

User journey:

1. Open UNMULAH
2. Choose Quran learning
3. Select Surah Al-Ikhlas
4. View trusted Quran text
5. Learn/review
6. Hide the Quran text
7. Start visual recitation
8. Browser requests camera permission
9. Camera detects the user's hand
10. AI recognizes Arabic fingerspelling / educational signing input
11. The recognized letter must immediately appear on screen
12. Build a live recognized sequence
13. User finishes recitation
14. Compare recognized sequence with the expected Quran reference
15. Detect errors where feasible:
   - deletion
   - insertion
   - substitution
   - sequence/order errors
16. Show clear visual feedback
17. Save attempt/progress locally

========================
VERY IMPORTANT UX FEATURE
========================

We need a "Live Sign Transcript" similar to live speech transcription.

Example:

User performs a hand sign.

The interface immediately displays:

"فهمت الإشارة: ب"

and optionally:

"الثقة: 92%"

If the user intended "ا" but the AI recognized "ب", the user must be able to see that immediately.

Do not silently build the sequence without showing what the AI recognized.

Use temporal stability before accepting a letter.

For example:
if prediction remains stable for several frames / a short duration, accept it.

If confidence is low or predictions fluctuate, do NOT guess.

Show:

"لم أتمكن من التعرف على الإشارة بوضوح، حاول مرة أخرى."

A manual confirm/retry interaction may be used if that improves reliability.

Also consider a simple demo page:

"جرّب الإشارة"

Camera → hand → predicted Arabic letter + confidence.

This could be useful for judging/demo purposes.

========================
AI ARCHITECTURE
========================

There are TWO completely different AI problems in this project.

Do not confuse them.

A) PERCEPTION AI — CORE MVP

Used for hand/fingerspelling recognition.

Possible pipeline:

Camera
→ MediaPipe Hands / Hand Landmarker
→ 21 hand landmarks
→ normalized landmark features
→ lightweight classifier
→ Arabic letter prediction
→ confidence
→ temporal stability
→ confirmed sequence
→ sequence comparison
→ feedback

We prefer lightweight client-side inference if practical.

Privacy preference:
Raw camera video should remain on the user's device whenever possible.
Do not record or upload video unless absolutely necessary.

B) KNOWLEDGE AI — OPTIONAL / STRETCH

If we later add an Islamic knowledge assistant, use:

LLM + RAG + trusted Islamic sources

Do NOT fine-tune an LLM just to teach it Quran/Tafsir.

RAG is NOT used for recognizing hand signs.

RAG is a stretch goal and must NOT delay the core visual recitation MVP.

========================
MODEL STRATEGY
========================

Do NOT immediately train a sign-recognition model from scratch.

Use this strategy:

Plan A:
Evaluate whether an existing suitable pretrained Arabic sign/fingerspelling model can be reused.

Prefer lightweight models compatible with:
MediaPipe landmarks / TensorFlow Lite / ONNX / browser inference.

Plan B:
If pretrained performance is insufficient, train or retrain a lightweight classifier using an appropriate licensed Arabic fingerspelling dataset.

Plan C:
Only consider custom data collection if necessary.

Before selecting any external model or dataset, document:

- source
- license
- classes supported
- expected input
- hand orientation assumptions
- limitations
- suitability for our use case

Do not fabricate accuracy numbers.

We must run our own evaluation and document real results.

RELIGIOUS / SCIENTIFIC SAFETY

"تفسير معاني القرآن الكريم بلغة الإشارة"

For memorization assessment, the system recognizes the user's educational/fingerspelling performance and compares it to a trusted Quran reference.

The AI is an assessment tool, not a religious authority.

Every Islamic source used in the product must be documented.
